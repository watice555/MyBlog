# 博客性能优化简报

- 方法：[huashu-flash](https://github.com/alchaincyf/huashu-flash/blob/master/SKILL.md)，采用先测量、功能护栏、逐项实验和交替配对复测；不全局安装 skill。
- 用户重点：首页、文章阅读、归档搜索、本地编辑器都重要。本轮优先检查共享加载路径，不修改文章、视觉设计、导航、SEO 或本地写入安全边界。
- 基线提交：`fa98248`。生产产物使用 `/MyBlog/` 子路径，基线构建和原始数据仅存于忽略的 `.local/perf/`。
- 阅读就绪：导航开始至 DOMContentLoaded 后字体完成加载，文章标题或首页最新文章标题具有非零尺寸，导航链接存在，再等待两次绘制帧。另报 FCP/LCP，不能将这个较严格的字体稳定指标等同于首次可见。
- 首页/文章为原生链接与静态内容，交互另做真实点击冒烟；归档需 React 挂载、搜索需真正返回匹配结果。编辑器需恢复检查完成且输入保留，用隔离 API 验证，不操作真实草稿。
- 主口径：冷缓存、新浏览器 context、所有请求统一 20ms 延迟、4×1024² bit/s 下行、3×1024² bit/s 上行、CPU 不限速、相同 gzip 服务；每个版本至少 10 次，A/B、B/A 交替；报告 p50/p75/p95。
- 桌面 1440×900、手机 390×844；本地回环浏览器会显示仅本地的编辑入口，两版本保持相同条件；公开编辑入口隔离由静态产物及既有测试检查。
- 目标：探索阅读就绪 p75 降低 50% 的可能性，不承诺达成；没有收益或护栏退化的实验回退。单次实验的字节变化仅是解释变量，未通过至少两次实验验证前不声称它能普遍预测体感速度。
- 护栏：现有 lint、应用测试、静态导出检查；新旧浏览器内容/SEO/链接一致，两种宽度截图一致；归档、搜索、关于、旧文章 hash 跳转正常。
- 发布：遵循用户项目约定，验证后提交并推送 main；不改 DNS/CDN。回滚用 git revert 对应优化提交，重新执行静态导出检查后推送。
